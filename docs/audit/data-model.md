# Current Data Model Audit: Argentine Domain Mapping

Closes #234

This is a static audit of the Supabase calls in `apps/web`, using checked-in code and documentation only. No database connection, export, credential, or migration was used. The requested `docs/domain-model.md` is not present in this checkout; comparisons below use the domain concepts documented in `docs/2-HOW-IT-WORKS.md`, `docs/4-ARCHITECTURE.md`, and the two analyses under `docs/next-steps/`. Where those sources do not define a target entity or relationship, the result is `unclear`.

## Method and Limits

- Searched TypeScript and JavaScript under `apps/web` for Supabase `.from(...)`, `.select(...)`, `.insert(...)`, `.update(...)`, `.upsert(...)`, and query filters.
- The inventory contains 14 distinct tables. Column lists include explicit select/filter/write references and fields declared in the app's hand-maintained interfaces at `apps/web/lib/types/database.ts`; these interfaces are not generated database types.
- `.select("*")` and `.select()` return whole rows but do not reveal their full column sets from code. No claim is made that the listed fields are exhaustive database schemas.
- Only the referenced calls and nearby inline types were inspected. No runtime requests were made.

### Column-Shape Caveats

- `select("*")` is used for `cooperatives`, `prosumers`, `meters`, `readings`, `certificates`, `retirements`, and `auth_challenges` (`apps/web/app/api/certificates/[id]/route.ts:24-26`; `apps/web/app/api/certificates/retire/route.ts:24-26`). It establishes whole-row reads, not the actual field list.
- `apps/web/lib/types/database.ts` contains handwritten interfaces for `Cooperative`, `Member`, `Meter`, `Reading`, `Certificate`, `Retirement`, and `MintLog`; it is neither generated database typing nor a complete definition of every queried table.
- The code writes `cooperatives.city` while its `Cooperative` interface has `location`; `readings.kwh_injected` is referenced in routes but omitted from its `Reading` interface. These are code-level shape inconsistencies, not verified database defects.
- `members` and `cooperative_members` are queried separately from `prosumers`; code does not prove their database constraints or whether they share identities.

## Legacy-Semantic Names and Gaps

Explicitly flagged names and relationships:

- `certificates` and `certificate_id` in `certificates`, `retirements`, and `mint_log` assume certificate semantics. Product docs currently qualify the token as a proto-certificate, while the target Argentine model document is missing.
- `retirements`, `buyer_address`, `buyer_name`, and `buyer_purpose` encode a buyer-retirement workflow; buyer identity is stored as text rather than a referenced organization in the observed writes.
- `prosumers`, `prosumer_id`, and `prosumer_address` encode a prosumer-specific actor model even though documented cooperative participants also include co-owners and mixed roles.
- `prosumers.cooperative_id` is a single-cooperative relation, while the separate `cooperative_members` table is read for admin role resolution. Canonical membership ownership is unclear.
- No Supabase `.from(...)` call was found for `trade`, `trades`, `marketplace_offer`, `marketplace_offers`, or `companies`. These names/entities are not current query tables in `apps/web` as inspected; their absence does not imply they should be added.

## Rename and Restructure Recommendations (Proposal)
